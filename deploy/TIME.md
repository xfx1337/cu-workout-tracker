# Развёртывание в TiMe (Mattermost)

Записка для того, кто поднимает бота в сети ЦУ. Здесь только то, что проверено
на живом сервере Mattermost, — включая грабли, на которые я уже наступил.

## Состояние ветки

Ветка `mattermost` **ещё не готова к боевому запуску**:

- транспорт, диспетчер, доменная логика, планировщик — готовы и покрыты тестами;
- **инфраструктура кнопок готова и проверена сквозняком**, но экраны бота пока
  описаны под реакции-эмодзи. Перевод экранов на кнопки в работе.

То есть если поднять сейчас — бот работает, но выбор будет реакциями, а не кнопками.
Рабочая версия для Telegram, которая крутится в проде, — на ветке `main`.

## Что нужно от админов TiMe

1. **Бот-аккаунт и его personal access token.**
2. **Адрес TiMe** — например `https://time.centraluniversity.ru`.
3. **Может ли сервер TiMe делать исходящие HTTP-запросы к боту?** Это главный
   вопрос: от него зависит, будут кнопки или реакции (см. ниже).

## Два режима, переключаются одной настройкой

| | `MM_PUBLIC_URL` задан | не задан |
|---|---|---|
| как выбирают | кнопки-attachments | реакции-эмодзи |
| что нужно | адрес бота, доступный серверу TiMe | ничего, только токен |
| экран | правится на месте, диалог в одном сообщении | каждый экран новым сообщением |

Код один и тот же, ветвление внутри `app/ui.py` и `BotContext.show()`.

## Грабли, проверенные на живом Mattermost

**1. Mattermost не зовёт интеграции на приватных адресах.**
Если бот стоит во внутренней сети, в логе будет:

```
IP 10.x.x.x is in a reserved range and not in AllowedUntrustedInternalConnections
```

Лечится в System Console → Environment → Developer, настройка
`ServiceSettings.AllowedUntrustedInternalConnections` — туда нужно внести адрес бота.
**Это просить у админов TiMe.** Если бот доступен по публичному домену с HTTPS,
настройка не нужна.

**2. Слушать надо и IPv6.**
`app/actions_server.py` биндится на `host=None` (оба стека). Привязка только к
`0.0.0.0` не сработает, если имя бота резолвится в IPv6 — Mattermost просто не
достучится, а ошибка будет невнятной.

**3. У кнопок обязателен `"type": "button"`.**
Без него Mattermost принимает пост, но пишет в лог `invalid action type` и грозит
ошибкой в будущих версиях. В `app/ui.py` уже проставлено.

**4. WebSocket на TiMe недоступен** — ingress режет upgrade. События получаем
опросом REST (`app/poller.py`, `POLL_INTERVAL_SECONDS`). На локальном стенде
WebSocket работает, на TiMe — нет, не удивляйся.

**5. `integration` не виден клиентам.**
Mattermost вырезает блок `integration` из props при отдаче в интерфейс, поэтому
одноразовый токен экрана в URL безопасен — подсмотреть его нельзя.

## Настройки

Минимум для запуска — `MM_URL`, `MM_TOKEN`, `ADMIN_EMAILS`. Полный список
с комментариями в [.env.example](../.env.example).

Админы задаются **почтой**, а не username: username в Mattermost человек может
сменить сам, почту выдаёт организация.

## Запуск

Так же, как телеграмная версия:

```bash
cp .env.example .env      # заполнить MM_URL, MM_TOKEN, ADMIN_EMAILS
docker compose up -d --build
```

Если включаешь кнопки — пробрось порт бота (`MM_LISTEN_PORT`, по умолчанию 8080)
наружу через обратный прокси с HTTPS и укажи адрес в `MM_PUBLIC_URL`.
В `docker-compose.yml` порт наружу намеренно не публикуется.

## Проверка

```bash
python -m tests.smoke          # 98 проверок домена, без сети
python -m tests.test_dispatch  # 17 проверок диспетчера
```

На живом Mattermost (нужен стенд или доступ к TiMe):

```bash
python -m tests.mm_live        # транспорт: личка, картинка, правка, реакции
python -m tests.mm_buttons     # кнопки целиком: клик через сервер MM до диспетчера
```

Локальный стенд поднимается за минуту:

```bash
docker compose -f docker-compose.mattermost-dev.yml -p mmdev up -d
python deploy/mm_dev_setup.py   # создаст бота, команду, тестовых студентов
```
