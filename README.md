# Бот записи на тренировки ЦУ

Бот для TiMe (Mattermost): студенты записываются на групповые тренировки,
администраторы ведут расписание, смотрят посещаемость и блокируют прогульщиков.
Админка живёт в том же боте.

> Ветка **`mattermost`** — рабочая версия для TiMe.
> Ветка `main` — старая версия для Telegram, оставлена как история.

Развёртывание: **[deploy/DEPLOY.md](deploy/DEPLOY.md)** (GitLab CI + Docker).
Что просить у админов TiMe и грабли Mattermost: **[deploy/TIME.md](deploy/TIME.md)**.

## Что умеет

**Студент**

- ничего не настраивает: личность берётся из мессенджера, где почта уже
  подтверждена организацией. Отдельного входа нет
- один раз подтверждает справку о группе здоровья и журнал по ТБ — без этого
  запись недоступна
- видит расписание **картинкой** — той же сеткой, что висит в универе, но со
  статусами прямо на карточках: «СВОБОДНО 12», «МЕСТ НЕТ», «ТЫ ЗАПИСАН», «ОТМЕНЕНА»
- листает недели, выбирает день, потом занятие; записывается и отменяет запись
- за 30 минут до начала получает напоминание с кнопкой «не смогу прийти»
- после тренировки отвечает, получилось ли прийти
- видит свою историю и счётчик пропусков

**Администратор**

- выбирает занятие по той же картинке недели: неделя → день → тренировка.
  Назад можно уйти на 12 недель, чтобы отметить посещаемость задним числом
- меняет расписание целиком через Excel: выгрузил неделю, поправил, загрузил —
  бот разложит её по всем неделям периода
- создаёт разовые тренировки, отменяет занятия (записанным уходит уведомление)
- смотрит записавшихся, отмечает посещаемость, ищет студентов, банит и разбанивает
- смотрит статистику и выгружает записи в CSV

**Автоматика**

- 25 мест на занятие, настраивается на каждое отдельно
- 3 пропуска без отмены → запись закрывается автоматически
- напоминания и опросы шлёт фоновый тик; состояние в БД, перезапуск не дублирует

## Два режима интерфейса

Кнопки в Mattermost устроены иначе, чем в Telegram: при клике **сервер Mattermost
сам делает HTTP-запрос к боту**. Поэтому боту нужен адрес, доступный этому серверу.

| | `MM_PUBLIC_URL` задан | не задан |
|---|---|---|
| как выбирают | кнопки под сообщением | реакции-эмодзи |
| что нужно | публичная ручка с HTTPS | ничего, только токен |
| экран | правится на месте, диалог в одном сообщении | каждый экран новым сообщением |

Код общий: обработчики описывают экран списком `Choice`, а способ отрисовки
выбирается в [app/ui.py](app/ui.py). Запасной режим существует на случай, если
в сети ЦУ ручку опубликовать не разрешат.

## Расписание

Хранится как недельный шаблон: админ правит одну неделю, бот раскладывает её на
семестр.

**Через Excel** — в админке кнопки «Выгрузить расписание» и «Загрузить расписание».
В файле `B2` — начало периода, `B3` — конец, с 6-й строки занятия на одну неделю.
Перед изменениями бот показывает, что получится, и ждёт подтверждения. Внутри
периода будущие занятия пересоздаются, прошедшие не трогаются (на них посещаемость),
студентам со слетевшими записями уходит уведомление.

**Первичная заливка** — [seed_trainings.py](seed_trainings.py):

```bash
docker compose exec bot python seed_trainings.py          # показать план
docker compose exec bot python seed_trainings.py --apply  # залить
```

## Картинка расписания

Сетку рисует [app/render.py](app/render.py) из данных БД, поэтому новое занятие
появляется на ней само. Картинка персональная: свои записи подсвечены. Шрифт
берётся системный (в образе стоит `fonts-dejavu-core`); если отрисовка упала,
бот не ломается — студент получает текстовый список, а traceback уходит в лог.

## Проверка

Без сети, гоняются в CI на каждый push:

```bash
python -m tests.smoke          # 98 проверок домена: места, страйки, Excel, отмены
python -m tests.test_dispatch  # 17 проверок диспетчера на фейковом мессенджере
```

На живом Mattermost — нужен стенд:

```bash
docker compose -f docker-compose.mattermost-dev.yml -p mmdev up -d
python deploy/mm_dev_setup.py   # заведёт бота, команду и тестовых студентов
python -m tests.mm_live         # транспорт: личка, картинка, правка, реакции
python -m tests.mm_buttons      # кнопки: клик через сервер MM доходит до диспетчера
```

`tests/mm_buttons.py` ценен тем, что проходит всю петлю целиком, включая
доступность бота для сервера Mattermost, — то, что на моках не проверить.

## Структура

```
app/
  bot.py            точка входа: поллер, приём кнопок, планировщик
  ui.py             экран как список Choice; отрисовка кнопками или реакциями
  actions_server.py HTTP-приём кликов, одноразовые токены экранов
  runtime.py        сессии пользователей, отправка и правка экранов
  poller.py         опрос REST вместо WebSocket (на TiMe upgrade режется)
  mm/client.py      клиент Mattermost: посты, файлы, реакции, события
  handlers/         common, student, admin — экраны и переходы
  services/         домен: записи, тренировки, страйки, Excel, статистика
  render.py         картинка расписания
  models.py         Student, Admin, Training, Booking, AuditLog
docker-compose.yml            бот + Postgres
docker-compose.caddy.yml      обратный прокси с HTTPS, если своего нет
.gitlab-ci.yml                тесты, сборка образа, выкладка
deploy/                       DEPLOY.md, TIME.md, Caddyfile, стенд
```

## Известные ограничения

- **Миграций нет**, схема создаётся кодом при старте. Новые таблицы подхватятся
  сами, новую колонку в существующей таблице придётся добавить руками.
- **Один процесс бота.** Гонку за последнее место это переживает: на Postgres
  запись сериализуется блокировкой строки занятия.
- **Состояние диалога в памяти.** Перезапуск сбрасывает незаконченный ввод
  (например, создание тренировки); на записи студентов не влияет.
- **Списки без пагинации** — до ~50 занятий на экран.
