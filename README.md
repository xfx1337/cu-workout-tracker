# Бот записи на тренировки ЦУ

> **Ветка `mattermost` — переезд в TiMe, в работе.**
> Доменный слой уже переведён на идентичность Mattermost, интерфейс переписывается.
> Рабочая версия для Telegram, которая крутится в проде, — на ветке `main`.
> README ниже пока описывает телеграмную версию.

Телеграм-бот: студенты записываются на тренировки, администраторы ведут расписание,
смотрят посещаемость и банят прогульщиков. Админка живёт в том же боте.

## Что умеет

**Студент**
- авторизуется один раз (telegram id → student id через ручку ЦУ)
- подтверждает плашку про справку о группе здоровья и журнал по ТБ — без этого запись недоступна
- видит расписание **картинкой** — той же сеткой, что висит в универе, но со статусами
  прямо на карточках: «СВОБОДНО 12», «МЕСТ НЕТ», «ТЫ ЗАПИСАН», «ОТМЕНЕНА», «ПРОШЛА»
- листает недели, выбирает день недели, потом конкретную тренировку
- записывается и отменяет запись
- за 30 минут до начала получает напоминание с кнопкой «не смогу прийти»
- после тренировки получает вопрос «удалось посетить?»
- видит свою историю и счётчик пропусков

**Администратор**
- выбирает занятие по той же картинке недели, что видит студент: неделя → день → тренировка
  (на карточках показана занятость, а не «ты записан»; назад можно уйти на 12 недель,
  чтобы отметить посещаемость задним числом)
- меняет расписание целиком через Excel: выгрузил неделю, поправил, загрузил обратно —
  бот сам разложит её по всем неделям периода
- создаёт разовые тренировки прямо в боте (название, тренер, описание, место, время, длительность, мест)
- отменяет тренировку — всем записанным автоматически уходит уведомление
- смотрит список записавшихся на любое занятие
- отмечает посещаемость по каждому студенту (переключением ❔ → ✅ → ❌ → ➖)
- ищет студента, банит и разбанивает вручную, сбрасывает пропуски
- смотрит статистику и выгружает все записи в CSV
- добавляет других админов

**Автоматика**
- 25 мест на занятие (настраивается на каждое отдельно)
- 3 пропуска без отмены → запись закрывается автоматически
- напоминания и пост-опросы шлёт фоновый тик, состояние в БД → перезапуск бота ничего не дублирует

## Быстрый старт

Нужен только Docker.

```bash
cp .env.example .env
```

Впиши в `.env` `BOT_TOKEN` и `ADMIN_USERNAMES`, затем:

```bash
docker compose up -d --build
```

Поднимутся два контейнера: `db` (Postgres 16) и `bot`. Схема создаётся сама при
первом запуске, данные лежат в volume `pgdata` и переживают пересборку образа.

```bash
docker compose logs -f bot      # смотреть лог
docker compose restart bot      # перезапустить после правок .env
docker compose down             # остановить (данные останутся)
docker compose down -v          # остановить и снести базу
```

### Без Docker

Тоже работает — например, для отладки. Postgres при этом можно взять из compose
(`docker compose up -d db`), а можно вообще обойтись SQLite, поменяв `DATABASE_URL`:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m app.bot
```

## Расписание

Расписание в ЦУ фиксированное и недельное, поэтому оно и хранится как недельный шаблон:
админ правит одну неделю, а бот сам раскладывает её на весь семестр.

### Через Excel (основной способ)

В админке две кнопки:

- **🗓 Выгрузить расписание** — бот отдаёт `.xlsx`: в `B2` начало периода, в `B3` конец,
  с 6-й строки занятия на одну неделю (день недели, время, название, тренер, описание,
  место, минут, мест).
- **📥 Загрузить расписание** — присылаешь этот файл обратно. Бот показывает, что
  получится (сколько создаст, сколько удалит, у скольких студентов слетят записи),
  и меняет что-либо только после подтверждения.

Загрузка перезаписывает расписание **внутри периода из файла**:

- будущие занятия периода удаляются и создаются заново из шаблона;
- прошедшие не трогаются — на них висит посещаемость;
- студентам, у кого была активная запись на удалённое занятие, уходит уведомление;
- повторная загрузка того же файла не плодит дубли.

День недели понимается и коротко (`Пн`), и полностью (`Понедельник`). Время — `18:30`
или ячейка формата «время». Пустые «минут»/«мест» заполняются значениями по умолчанию.
Если в файле ошибка, бот перечислит проблемы с номерами строк и ничего не изменит.

Разовое занятие (пересдача, мастер-класс) удобнее добавить кнопкой
**➕ Новая тренировка**, а отменить — на карточке занятия. Excel для этого не нужен.

### Через скрипт (первичная заливка)

```bash
docker compose exec bot python seed_trainings.py          # посмотреть план
docker compose exec bot python seed_trainings.py --apply  # залить
```

Расписание лежит в `SCHEDULE` в [seed_trainings.py](seed_trainings.py). Повторный запуск
безопасен: занятия с тем же названием и временем не дублируются. Сейчас там официальное
расписание: 12 занятий в неделю (пн–пт, утренний слот 8:30 по вт/чт и вечерние 18:30
и 19:40), все по 60 минут, 25 мест. Тексты в `DESCRIPTIONS` — рабочий вариант,
их стоит согласовать с заказчиком.

## Авторизация

Полноценного SSO нет — по договорённости бот дёргает ручку ЦУ и получает student id.

```
GET {AUTH_API_URL}?telegram_id=123456789
Authorization: Bearer {AUTH_API_TOKEN}   # если задан

200 → {"student_id": "s12345", "full_name": "Иван Иванов", "email": "ivan@centraluniversity.ru"}
404 → студент не найден
```

Пока `AUTH_API_URL` пуст, работает **заглушка**: любой пользователь получает
`student_id = stub-<telegram_id>`. Бот громко пишет об этом в лог при старте.
Вся логика — в [app/auth.py](app/auth.py), при появлении реальной ручки менять только её.

Если ЦУ отдаёт ссылку для логина, положи её в `AUTH_LOGIN_URL` — в боте появится кнопка
«Войти на сайте ЦУ», а рядом «Я вошёл», по которой бот сходит за student id.

## Картинка расписания

Сетку рисует [app/render.py](app/render.py): колонки — дни недели, строки — время начала,
всё берётся из БД, так что новое занятие появляется на картинке само. Цвета занятий заданы
в `PALETTE` по названию; для незнакомого названия берётся цвет из запасной палитры.

Картинка перерисовывается на каждый показ — статусы всегда актуальные, и у каждого студента
своя (его записи подсвечены белой рамкой и плашкой «ТЫ ЗАПИСАН»).

Шрифт ищется среди системных (Arial → DejaVu → Liberation → Noto). **На Linux-сервере
поставь шрифты**, иначе картинка не соберётся:

```bash
apt-get install -y fonts-dejavu-core
```

Если отрисовка всё же упала, бот не ломается: студенту уходит текстовый список тренировок,
а в лог — traceback.

## Настройки (`.env`)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `BOT_TOKEN` | — | токен бота |
| `ADMIN_USERNAMES` | — | суперадмины через запятую, без `@` |
| `DATABASE_URL` | — | `postgresql+asyncpg://...`; в compose задаётся автоматически |
| `POSTGRES_USER` / `_PASSWORD` / `_DB` | `workout` | реквизиты базы для compose |
| `POSTGRES_PORT` | `5432` | порт базы на localhost (наружу не торчит) |
| `TZ_NAME` | `Europe/Moscow` | часовой пояс расписания |
| `AUTH_API_URL` | пусто | ручка ЦУ; пусто = заглушка |
| `DEFAULT_CAPACITY` | `25` | мест на занятие по умолчанию |
| `REMINDER_MINUTES_BEFORE` | `30` | за сколько минут напомнить |
| `CANCEL_DEADLINE_MINUTES` | `0` | за сколько минут до старта закрыть отмену |
| `NO_SHOW_LIMIT` | `3` | пропусков до автоблокировки |
| `SILENCE_GRACE_HOURS` | `24` | сколько ждать ответа на пост-опрос |
| `SELF_REPORTED_ABSENCE_COUNTS` | `false` | считать ли страйком честное «не смог прийти» |
| `SILENCE_COUNTS` | `true` | считать ли страйком молчание после опроса |

## Как считаются пропуски

| Что сделал студент | Отметка | Страйк |
|---|---|---|
| Отменил запись до начала | ➖ уважительно | нет |
| Ответил «был» на пост-опрос | ✅ | нет |
| Ответил «не получилось» | ❌ или ➖ | по `SELF_REPORTED_ABSENCE_COUNTS`, по умолчанию нет |
| Промолчал `SILENCE_GRACE_HOURS` | ❌ | да (если `SILENCE_COUNTS`) |
| Админ отметил вручную | как отметил | ❌ даёт страйк, остальные — снимают |

Отметка админа перебивает всё: поставил ✅ или ➖ — страйк снимается, автобан снимается вместе с ним.
Ручной бан админом снимается только вручную.

## Админы

`ADMIN_USERNAMES` из `.env` — суперадмины: их нельзя снять из бота, и только они добавляют
других админов. Новый админ добавляется по `@username`; права появятся, когда он напишет боту
(telegram не даёт узнать user id по username заранее — бот запоминает его при первом заходе).

## Проверка

```bash
python -m tests.smoke
```

151 проверка без сети: лимит мест, гонка за последнее место, отмены, страйки и автобан,
ручной бан, отмена тренировки, статистика, CSV, отрисовка картинки и статусы на ней,
выгрузка/загрузка расписания в Excel и разбор кривых файлов, клавиатуры.

По умолчанию гоняется на временной SQLite. Тот же набор прогоняется на боевом Postgres —
база должна быть отдельной, схема в начале сносится:

```bash
docker compose exec -T db psql -U workout -d workout -c "CREATE DATABASE workout_test OWNER workout;"
SMOKE_DATABASE_URL=postgresql+asyncpg://workout:workout@127.0.0.1:5432/workout_test python -m tests.smoke
```

Отдельно `check_dispatch` прогоняет настоящие апдейты через диспетчер с подменённой сетевой
сессией. Это ловит то, что не видно при простой сборке роутеров — например, что мидлварь
зарегистрирована как inner и потому выполняется **после** фильтров, из-за чего фильтр
`IsAdmin` не получает `admin` и весь админский роутер молча съедает апдейты.

## Деплой

### Первый раз

1. **Доступ по ключу** (пароли в скриптах не нужны, и это безопаснее):

   ```powershell
   type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh root@СЕРВЕР "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
   ```

2. **Готовим `.env`** — возьми [deploy/.env.prod.example](deploy/.env.prod.example),
   положи в корень как `.env`, впиши `BOT_TOKEN`, `ADMIN_USERNAMES` и **свой** `POSTGRES_PASSWORD`.

3. **Заливаем и запускаем**:

   ```powershell
   powershell -ExecutionPolicy Bypass -File deploy\push.ps1 -Server root@СЕРВЕР
   ssh root@СЕРВЕР "bash /opt/cu-workout-tracker/deploy/bootstrap.sh"
   ```

`bootstrap.sh` ставит Docker, включает автозапуск, собирает образ и поднимает бота.
Запускать повторно безопасно. Он же откажется стартовать, если в `.env` остался
дефолтный пароль базы или пустой токен.

### Обновление

```powershell
powershell -ExecutionPolicy Bypass -File deploy\push.ps1 -Server root@СЕРВЕР -SkipEnv
ssh root@СЕРВЕР "cd /opt/cu-workout-tracker && docker compose up -d --build"
```

`-SkipEnv` не перезаписывает серверный `.env` локальным.

### Важно: один токен — один бот

Telegram не даёт двум процессам читать апдейты одного бота. Перед запуском на сервере
останови локальный стек, иначе оба будут драться за апдейты:

```bash
docker compose down
```

Для параллельной отладки заведи у BotFather второго бота и подставь его токен локально.

### Эксплуатация

```bash
docker compose logs -f bot                      # лог
docker compose restart bot                      # после правки .env
docker compose exec -T db pg_dump -U workout workout > backup.sql   # бэкап
docker compose exec -T db psql -U workout -d workout < backup.sql   # восстановление
```

Оба сервиса с `restart: unless-stopped`, так что после перезагрузки сервера
поднимутся сами.

### Порт Postgres

В `docker-compose.yml` порт базы наружу **не публикуется**: бот ходит к ней по внутренней
сети compose как `db:5432`. Это важно на сервере, где уже крутится чужой Postgres, —
иначе контейнер не стартует с `Bind for 127.0.0.1:5432 failed: port is already allocated`.

Локально порт всё же нужен (зайти `psql`, прогнать тесты на боевом движке), поэтому его
пробрасывает [docker-compose.override.yml](docker-compose.override.yml) — compose
подхватывает этот файл автоматически, а [deploy/push.ps1](deploy/push.ps1) его на сервер
не копирует.

## Известные ограничения

- **Схема БД создаётся через `create_all`**, миграций нет. Новые таблицы подхватятся сами,
  а вот новую колонку в существующей таблице придётся добавлять руками
  (`ALTER TABLE ... ADD COLUMN`). Если схема начнёт меняться часто, стоит завести alembic.
- **Один процесс бота.** Больше одного long-polling инстанса на один токен телеграм не даст.
  Гонку за последнее место это переживает: на Postgres запись на занятие сериализуется
  блокировкой строки тренировки (`SELECT ... FOR UPDATE`), на SQLite — пересчётом очереди
  после вставки.
- **Состояние FSM в памяти.** Перезапуск во время создания тренировки сбросит незаконченный
  ввод; на поведение студентов не влияет.
- **`build_dispatcher()` можно вызвать только раз за процесс** — роутеры модульные синглтоны.
  Для бота это нормально, в тестах диспетчер кэшируется.
- **Студент не пишет боту ни одного сообщения** — весь его сценарий на инлайн-кнопках.
  Текст вводят только админы: название тренировки, дата, поиск студента.
- **Списки без пагинации** — до ~50 будущих тренировок и 20 результатов поиска на экран.
  Для семестрового расписания хватает, для года — нет.
